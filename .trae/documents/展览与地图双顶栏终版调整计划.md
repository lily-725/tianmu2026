# 展览与地图双顶栏终版调整计划

## Summary

- 目标：围绕用户最新要求，完成展览页与地图页的导航重设计收尾，确保全站只保留一套明确的站点级顶部导航，同时保证文案、层级、跳转和样式统一。
- 成功标准：
  - 首页顶部品牌为 `天穆地方史`
  - 展览页顶部品牌为 `天穆六百年`
  - 地图页顶部品牌为 `地图里的天穆村`
  - 展览页原有顶部层级导航职责移入侧边栏或移动端目录，并支持“返回上一级”
  - 展览页与地图页不再产生“双顶栏”观感
  - 页面无重叠、无错乱、可正常跳转，且 `lint`、`build` 通过
- 当前判断：核心重构代码已存在于仓库中，后续执行阶段应以“核验现状 + 必要微调 + 最终验收”为主，而不是重新发明导航结构。

## Current State Analysis

### 1. 路由与页面挂载已明确

- `src/App.tsx`
  - 首页为 `/`
  - 地图页为 `/map`
  - 展览入口为 `/exhibition`
  - 展览内部页为 `/about`、`/foreword`、`/hall`、`/hall/:exId`、`/hall/:exId/:unitId`、`/collection`、`/collection/:id`、`/team`
- 这说明本次不需要改路由结构，只需要在现有壳层中重新分配导航职责。

### 2. 站点级顶栏已经支持页面变体

- `src/components/SiteTopNav.tsx`
  - 已存在 `home | exhibition | map` 三种 `variant`
  - 品牌文案已按页面变体分配：
    - `home` -> `天穆地方史`
    - `exhibition` -> `天穆六百年`
    - `map` -> `地图里的天穆村`
  - 一级导航仍统一指向 `首页 / 展览 / 地图`
- 结论：品牌标题切换这一部分已具备实现基础，执行时重点是确认挂载位置与视觉层级是否最终合理。

### 3. 展览页已开始将层级导航迁到侧边栏

- `src/components/Layout.tsx`
  - 顶部保留 `SiteTopNav variant="exhibition"`
  - 已存在 `getExhibitionContext(pathname)`，能根据当前路径推导：
    - 单元详情 -> 返回专题详情
    - 专题详情 -> 返回漫步展厅
    - 藏品详情 -> 返回浏览展陈
    - 展览一级页 -> 返回展览首页
    - 展览首页 -> 返回网站首页
  - 桌面侧栏已有：
    - 当前层级 `Current Layer`
    - 当前层级说明
    - 返回上一级链接
  - 移动端目录已有：
    - `打开展览目录`
    - 返回入口
    - 内部目录项
- 结论：展览页的结构方向已经符合需求，执行阶段主要验证是否还残留“第二顶部栏”观感，以及各详情页返回链路是否完全正确。

### 4. 地图页已将第二头部弱化为说明区

- `src/modules/map/components/Header.tsx`
  - 顶部保留 `SiteTopNav variant="map"`
  - 下方不再重复显示大标题“地图里的天穆村”
  - 现为 `Period Overview` + 当前时期 + 说明文案 + `ACTIVE PERIOD` 的组合
- `src/index.css`
  - 已有 `.map-header-context` 与 `.map-header-badge` 样式
  - 地图模块顶栏品牌字号已做单独微调
- 结论：地图页已具备“一个顶栏 + 一个内容说明区”的结构，执行阶段重点验证视觉上是否仍像双栏叠加，尤其是移动端和窄屏。

### 5. 样式层已经有统一主题基础

- `src/index.css`
  - 已有 `.home-module-theme`、`.exhibition-module-theme`、`.map-module-theme`
  - 已有统一的 `.site-top-nav` 样式体系
  - 已有展览侧栏卡片样式 `.exhibition-sidebar-card`
  - 已有地图说明区样式 `.map-header-context`
- 风险点：
  - 仍有一些地图移动端样式通过宽泛的 `header` 选择器生效，需要确认不会把说明区重新拉成“第二顶栏”
  - 展览移动端顶部条虽然不再是站点导航，但仍要确认它只承担“当前层级 + 菜单开关”，不会与顶栏视觉冲突

## Assumptions & Decisions

- 保留 `SiteTopNav` 作为全站唯一站点级顶部导航，不新增新的顶部导航组件。
- 不调整 `src/App.tsx` 的路由路径和页面信息架构。
- 展览页中：
  - 顶部只保留 `SiteTopNav`
  - 层级导航不再以 breadcrumb 顶条形式出现
  - 层级返回交由侧边栏和移动端目录承接
- 地图页中：
  - 顶部只保留 `SiteTopNav`
  - `Header.tsx` 仅承担“时期说明区”，不再承担品牌主标题
- 首页不做结构性改动，只校验其与统一顶栏的关系是否稳定。
- 如果浏览器回归发现仍有明显双顶栏观感，优先通过间距、字号、背景层级、边框和 sticky 行为微调解决，而不是重写组件结构。

## Proposed Changes

### 1. 校验并稳固站点级顶栏品牌与高亮逻辑

- 文件：`src/components/SiteTopNav.tsx`
- 做什么：
  - 核对三种 `variant` 的品牌文案与副标题是否与用户要求完全一致
  - 核对 `首页 / 展览 / 地图` 的高亮匹配是否覆盖所有展览子路由与地图子路径
- 为什么：
  - 这是“唯一顶部导航”成立的前提，品牌文案必须准确，一级导航必须可靠
- 怎么做：
  - 浏览实际页面并检查：
    - `/`
    - `/exhibition`
    - `/hall/...`
    - `/collection/...`
    - `/map`
  - 如发现高亮或文案错位，再最小化微调 `BRAND_BY_VARIANT` 或 `NAV_ITEMS` 匹配规则

### 2. 终检展览页“顶部职责下沉到侧栏”的完整性

- 文件：`src/components/Layout.tsx`
- 做什么：
  - 确认桌面侧栏和移动端目录已完整接手原顶部层级导航职责
  - 确认没有遗留 breadcrumb 顶条、重复标题横条或无效返回层级
- 为什么：
  - 用户的核心要求之一就是把原“首页 / 漫步展厅式”的顶部层级功能移到侧边栏，并可变为“返回上一级”
- 怎么做：
  - 按页面逐项核验：
    - `/exhibition` 应显示“返回网站首页”
    - `/hall` 应显示“返回展览首页”
    - `/hall/:exId` 应显示“返回漫步展厅”
    - `/hall/:exId/:unitId` 应显示“返回专题详情”
    - `/collection/:id` 应显示“返回浏览展陈”
  - 若文案或路径不符，仅调整 `getExhibitionContext(pathname)`，不改动整体布局

### 3. 消除展览移动端可能残留的“双顶栏观感”

- 文件：`src/components/Layout.tsx`
- 文件：`src/index.css`
- 做什么：
  - 检查移动端 `Current Layer + 打开展览目录` 条是否在视觉上被误读为第二顶栏
  - 必要时弱化该区域的尺寸、背景、边框或与 `SiteTopNav` 的粘连关系
- 为什么：
  - 即便功能职责已正确，只要视觉层级过强，用户仍会感知成双顶栏
- 怎么做：
  - 优先考虑以下微调方向：
    - 降低背景对比
    - 缩短垂直高度
    - 减少边框强调
    - 增加与 `SiteTopNav` 的内容间距
  - 保证它更像“页面上下文条”，而不是“第二导航条”

### 4. 终检地图页说明区是否已经脱离“第二导航条”语义

- 文件：`src/modules/map/components/Header.tsx`
- 文件：`src/index.css`
- 做什么：
  - 检查地图页顶部是否只剩一套明显主导航
  - 检查下方说明区是否只承担时期说明，不再与顶栏争抢品牌层级
- 为什么：
  - 地图页此前最容易出现“站点顶栏 + 模块顶栏”叠加
- 怎么做：
  - 重点观察：
    - 是否还存在重复主标题
    - `Period Overview` 与 `ACTIVE PERIOD` 是否只是说明信息
    - 说明区背景、边框、字号是否过强
  - 若仍显得像第二栏，优先微调：
    - 上下内边距
    - 文案字号层级
    - 分隔线和边框强度
    - 桌面与移动端布局切换

### 5. 复核地图移动端规则是否误伤新的头部结构

- 文件：`src/index.css`
- 做什么：
  - 复核 `@media (max-width: 768px)` 内所有与 `.map-module-theme header` 相关的规则
  - 确保它们不会把 `SiteTopNav` 与说明区一起压成不合理的复合头部
- 为什么：
  - 当前样式中存在广义 `header` 选择器，容易在新结构下产生意外耦合
- 怎么做：
  - 如果发现误伤，则改为更精确的类选择器，例如只命中地图说明区容器，而不是地图页整个 `header`
  - 保持地图主体、时间轴、详情栏高度和滚动行为不变

### 6. 进行最终工程与浏览器回归

- 文件范围：
  - `src/components/SiteTopNav.tsx`
  - `src/components/Layout.tsx`
  - `src/modules/map/components/Header.tsx`
  - `src/index.css`
  - 如有必要，`src/modules/map/App.tsx`
- 做什么：
  - 跑工程校验并逐页回归页面效果
- 为什么：
  - 本次问题本质上属于导航层级与布局表现问题，单看代码不足以确认“无重叠、无错乱”
- 怎么做：
  - 执行：
    - `npm run lint`
    - `npm run build`
    - `npm run dev`
  - 浏览器回归：
    - `/`
    - `/exhibition`
    - `/hall`
    - `/hall/:exId`
    - `/hall/:exId/:unitId`
    - `/collection/:id`
    - `/map`
  - 检查桌面端和移动端两套布局

## Implementation Order

1. 先复核 `SiteTopNav.tsx` 的品牌与高亮逻辑，确认无需结构性改动。
2. 复核 `Layout.tsx` 的 `getExhibitionContext` 和桌面/移动端层级入口，修正任何返回链路偏差。
3. 聚焦展览移动端顶部条，必要时在 `src/index.css` 中弱化其“第二导航条”观感。
4. 复核 `Header.tsx` 与地图相关样式，确保说明区不是第二主导航。
5. 清理地图移动端宽泛 `header` 规则带来的潜在耦合。
6. 执行 `lint`、`build` 与浏览器全链路回归，确认无错乱、无跳转问题。
