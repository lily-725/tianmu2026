# 全站顶部导航栏重设计计划

## Summary

- 目标：为整站新增一套统一的顶部导航栏，覆盖 `首页`、`展览`、`地图` 三个一级入口，并保证在所有模块中都可正常跳转。
- 设计方向：采用统一品牌风，跨首页、展览、地图共用同一信息架构与交互逻辑，但在颜色、透明度、边框和背景材质上根据页面主题做轻微变体。
- 导航策略：以顶部导航栏承担全站一级导航职责；保留展览侧边栏与地图功能头部，但将它们降级为模块内部信息/功能容器，不再承担主要站点级跳转职责。
- 约束：不改动现有路由结构；不破坏首页 hero、展览编目式布局、地图三栏结构与已有动画/滚动/响应式行为。

## Current State Analysis

### 路由与壳层现状

- `src/App.tsx`
  - 根路由为 `/`，首页使用 `SiteHome`。
  - 地图模块使用 `/map`，直接挂载 `MapApp`。
  - 展览模块不是单一路径，而是 `/exhibition`、`/about`、`/foreword`、`/hall`、`/collection`、`/team` 等多条路径共用 `ExhibitionShell`。
- 当前没有统一的“站点级顶部导航”壳层；站点导航被拆散在各模块内部。

### 展览模块现状

- `src/components/Layout.tsx`
  - 桌面端为左侧固定侧边栏导航，移动端为顶部汉堡菜单。
  - 现有导航项主要是展览内部页面：`关于天穆`、`展览前言`、`漫步展厅`、`浏览展陈`。
  - 站点级入口只有 Logo 链接到 `/exhibition`，没有 `首页`、`地图` 一级导航。
  - 主内容区内部还有 breadcrumb 区域。
- 风险点：
  - 如果直接加顶栏，需重新分配桌面布局，避免“顶部导航 + 左侧大侧栏”造成信息层级冲突。

### 首页现状

- `src/pages/SiteHome.tsx`
  - 当前没有顶部导航。
  - Hero 区左右分栏，右侧通过两个大按钮跳转到 `/exhibition` 与 `/map`。
  - 页面视觉依赖大标题、水印、印章、竖排说明和极简留白。
- 风险点：
  - 顶栏不能破坏首页首屏构图，建议使用悬浮/透明式顶栏而非实体厚重导航。

### 地图模块现状

- `src/modules/map/App.tsx`
  - 地图模块自身是完整的三段式布局：顶部 `Header` + 左侧时间轴 + 中间地图 + 右侧详情。
- `src/modules/map/components/Header.tsx`
  - 当前头部只负责模块标题与副标题，不包含站点级导航。
- 风险点：
  - 顶部导航若直接替换 `Header`，可能影响地图页垂直空间和移动端布局。
  - 更稳妥的方式是将站点级导航并入 `Header`，保留模块标题区和结构节奏。

### 样式与主题现状

- `src/index.css`
  - 已通过 `.home-module-theme`、`.exhibition-module-theme`、`.map-module-theme` 做三套主题变量隔离。
  - 展览与地图模块都已有各自的 `header/nav` 响应式规则，顶部导航改造需避免与这些选择器冲突。
- 结论：
  - 最低风险做法是新增独立组件类名，而不是继续复用现有 `header/nav` 通用选择器。

## Assumptions & Decisions

- 已确认采用“顶部主导航”为主：新增统一顶栏，但不删除展览侧栏和地图页功能头部。
- 已确认采用“统一品牌风”：顶栏在三个模块中保持一致的信息架构、选中态、跳转逻辑和移动端菜单行为。
- 站点一级导航固定为三项：
  - `首页` -> `/`
  - `展览` -> `/exhibition`
  - `地图` -> `/map`
- `展览` 顶栏高亮规则不只匹配 `/exhibition`，还需覆盖其整组子路由：
  - `/about`
  - `/foreword`
  - `/hall`
  - `/collection`
  - `/team`
- 不调整现有业务路由，不将展览内部页面整体迁移到 `/exhibition/...`，以避免扩大改动范围。
- 移动端顶栏与桌面端顶栏共享同一站点级导航源，使用抽屉/全屏菜单承载站点一级跳转。

## Proposed Changes

### 1. 新增统一顶部导航组件

- 文件：`src/components/SiteTopNav.tsx`（新增）
- 做什么：
  - 新建一个全站复用的顶部导航组件。
  - 输出桌面与移动端两套表现，但共享相同导航数据源与当前路由高亮逻辑。
  - 提供可配置外观变体，例如：
    - `home`
    - `exhibition`
    - `map`
  - 提供可配置布局行为，例如：
    - `overlay`：首页首屏悬浮覆盖
    - `sticky`：展览/地图页吸顶
- 为什么：
  - 站点级导航需要统一，而当前首页、展览、地图分别在不同壳层。
  - 单独组件可以避免把逻辑散落到 `Layout.tsx`、`SiteHome.tsx`、`map/Header.tsx` 三处重复维护。
- 怎么做：
  - 使用 `react-router-dom` 的 `Link` + `useLocation()` 实现 active state。
  - 将展览整组路径映射到同一个“展览”选中态。
  - 使用 `motion/react` 为菜单展开、hover 下划线、active pill 提供轻量动效。
  - 桌面端采用低高度横向主导航；移动端用按钮展开站点导航面板。

### 2. 在首页接入顶栏

- 文件：`src/pages/SiteHome.tsx`
- 做什么：
  - 在首页最外层或首屏容器顶部接入 `SiteTopNav`。
  - 保留现有首页两个大 CTA 按钮，不删。
- 为什么：
  - 用户要求全站统一的顶部导航，首页必须具备清晰的一级入口。
  - 保留现有 CTA 可以兼顾“顶部快速跳转”和“首屏重点引导”。
- 怎么做：
  - 采用 `overlay` 风格，让顶栏绝对定位或悬浮在 hero 上方。
  - 使用透明背景、细边框、轻模糊或淡金/墨色文字，避免压坏首页构图。
  - 适当增加顶部安全间距，确保标题与顶栏不重叠。

### 3. 改造展览壳层以接入顶栏

- 文件：`src/components/Layout.tsx`
- 做什么：
  - 将展览模块当前“桌面左侧栏 + 移动端顶部栏”的结构改造为：
    - 站点级顶部导航
    - 展览内部侧边栏/目录导航
    - 主内容区
  - 移动端保留内部菜单能力，但站点级跳转统一交给新顶栏。
- 为什么：
  - 这是本次改动的核心难点：需要在不丢失展览内部目录的前提下，引入站点级一级导航。
- 怎么做：
  - 桌面端将根布局从“左右分栏为主”改为“顶部一行 + 下方左右分栏”。
  - 左侧栏继续负责展览内部页面目录，不再承担首页/地图跳转。
  - 调整 breadcrumb 与主内容顶部间距，使其与新顶栏顺序清晰。
  - 移动端将 `天穆六百年 + 汉堡菜单` 的旧 header 职责拆分：
    - 新顶栏负责一级导航
    - 原菜单仅作为展览内部目录菜单

### 4. 将地图页头部整合为“站点导航 + 模块标题”

- 文件：`src/modules/map/components/Header.tsx`
- 做什么：
  - 在地图页头部内接入 `SiteTopNav`，并保留“地图里的天穆村”标题与副标题。
- 为什么：
  - 地图页已有成熟的头部结构，直接替换为全局壳层风险更大。
  - 将顶栏嵌入 `Header` 可以最大限度保持地图布局稳定。
- 怎么做：
  - 将现有 `Header` 改为上下两段：
    - 上段：站点级顶栏
    - 下段：地图模块标题、副标题与必要留白
  - 控制总高度增长，避免压缩地图可视区域过多。
  - 对移动端延续现有地图页响应式逻辑，但需为新增顶栏补齐高度与间距规则。

### 5. 视情况调整地图页容器间距

- 文件：`src/modules/map/App.tsx`
- 做什么：
  - 如 `Header` 高度变化导致主内容区溢出或挤压，则同步调整根容器高度分配。
- 为什么：
  - 地图页是 `h-screen` 三栏布局，顶部增加导航后容易出现内容被截断。
- 怎么做：
  - 保持 `Header` 占据固定高度或自然高度，主内容区仍由 `flex-1` 接管。
  - 在移动端媒体查询场景下复核时间轴与侧栏堆叠顺序。

### 6. 新增顶栏样式体系与模块变体

- 文件：`src/index.css`
- 做什么：
  - 为新组件新增独立的站点导航样式类，例如：
    - `.site-top-nav`
    - `.site-top-nav--home`
    - `.site-top-nav--exhibition`
    - `.site-top-nav--map`
  - 为移动端菜单、active 状态、hover 下划线、背景模糊、主题变量映射添加样式。
- 为什么：
  - 当前全局样式已经有模块级隔离，顶栏需要建立一套不污染现有 header/nav 规则的新命名空间。
- 怎么做：
  - 使用主题变量继承各模块颜色，但统一交互语言：
    - 首页：更轻、更透明
    - 展览：纸本浅底、细边框
    - 地图：档案灰底、轻技术感
  - 避免复用 `.nav-button`、`.map-module-theme header` 这类易冲突选择器。

### 7. 小范围接入壳层

- 文件：`src/App.tsx`
- 做什么：
  - 仅在必要时调整壳层传参或结构，让首页、展览、地图都能接入统一顶栏组件。
- 为什么：
  - 路由本身已经合理，不应大改；这里只做轻量壳层接线。
- 怎么做：
  - 保持原路由不变。
  - 继续沿用 `ExhibitionShell` 与 `MapPage`，只在它们内部消费新组件。

## Implementation Order

1. 新增 `SiteTopNav.tsx`，先完成导航数据结构、active route 判断、桌面/移动端交互。
2. 在 `src/index.css` 增加统一顶栏样式和三套主题变体。
3. 接入首页 `SiteHome.tsx`，调通悬浮效果与首屏间距。
4. 改造展览 `Layout.tsx`，实现“顶部站点导航 + 左侧展览目录 + 主内容”结构。
5. 改造地图 `Header.tsx`，实现“顶部站点导航 + 地图标题区”。
6. 如有需要微调 `src/modules/map/App.tsx` 的高度与布局分配。
7. 最后整体验证桌面/移动端、首页/展览/地图三大入口跳转与高亮。
